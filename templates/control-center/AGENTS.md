# Control-center instructions

## Purpose

This folder routes durable projects and documents stable operating rules. It is not a store for project source code, private logs, or chat transcripts.

## Project routing

- Consult `PROJECTS.md` before entering a registered project.
- After routing, read the project's own `AGENTS.md`, README, specifications, and only the state files necessary for the task.
- Add a project only when it genuinely needs long-term ownership.

## Information hygiene

- Keep the registry thin: name, root, lifecycle, and a short routing label are enough.
- Treat code, project documents, and data in the project folder as the source of truth.
- Create a short `CURRENT.md` inside a project only when temporary cross-task state is necessary; replace it rather than accumulating a diary.
- Do not store credentials, personal data, private local paths, or sensitive operational status here.

# Contributing

Thank you for improving the starter kit.

## Principles for changes

- Keep the default setup understandable and reversible.
- Avoid personal assumptions, vendor lock-in, and platform-specific behavior unless documented.
- Do not add real user data, credentials, or private paths to examples or tests.
- Update documentation whenever behavior changes.

## Pull requests

Describe the user problem, the chosen trade-off, and how you tested the change. Small, focused pull requests are easiest to review.

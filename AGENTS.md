# Project instructions

## Purpose

Build a public, privacy-first starter kit for organizing Codex work through a local control center and independently owned projects.

## Non-negotiables

- Never add personal paths, project names, conversations, credentials, health data, financial data, or user-specific status to tracked files.
- Keep the public template platform-neutral unless a platform-specific variant is intentional and documented.
- Treat source files and project documentation as the source of truth; do not introduce opaque memory stores by default.
- Prefer a minimal install that users can understand and safely undo.

## Documentation style

- Write README-facing material in clear English for an international audience.
- Explain trade-offs and defaults, not just commands.
- Keep examples fictional and generic.

## Before public release

- Add a license.
- Add a security/privacy review.
- Test the bootstrap flow in a clean directory.
- Confirm all tracked files contain no personal data.
